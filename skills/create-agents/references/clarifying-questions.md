# 追問協議：解析估算表、補齊資訊、寫 AGENTS.md 時卡住怎麼問

這份技能有三個地方常常卡在「猜還是問」：步驟 1 解析估算表時遇到打錯欄或語意含糊的儲存格、
步驟 2 判斷作業性質、步驟 3 補齊估算表沒寫的資訊。猜錯的代價都不小——輕則 AGENTS.md
要重寫，重則代理人在客戶生產環境上做錯事。這份文件定義卡住時怎麼問，取代「想到就問」
或「一次把所有可能想到的都問一輪」。

## 先分「事實」與「決策」

不是所有不確定都要問使用者。先判斷這件事能不能自己查到答案：

- **事實**：讀估算表本身、`ls` 技能目錄、`grep` 檔案內容就找得到的，自己去查，不要包成問句丟給使用者。
  例：專案名稱通常在檔名或表頭；已安裝的技能清單用 `ls ~/.claude/skills/` 查；
  「項目備註」欄有沒有寫替代工具，直接讀估算表。
- **決策**：只有使用者能拍板的才問。例：作業性質是唯讀還是變更型（表上的動詞可以兩邊解讀時）、
  要不要同步到外部平台、代理人的角色定位要叫什麼。

判斷不出來時預設它是事實——先花一次查證的成本，總比多問使用者一題便宜。真的查不到，
或查到的結果彼此矛盾（例如備註欄同時暗示唯讀與變更），才升級成決策題。

## 一輪問完該問的，不要用猜的填未來才問得出的題

當下卡住的決策題一次列成一輪，每題附上你的建議答案，讓使用者用「同意／不同意」就能過：

```
❓ **Q1** - **<問題標題>**：<問題內容，可以是多段或多選>

➡️ <你的建議答案>
```

同一輪只問「前提已經齊備」的題目。有些題目要等使用者先回答另一題才問得出來——
例如「是否需要同步到外部平台」答了「要」，才問得出「同步方向限制（只准讀不准寫？）」；
答了「不要」，這題就直接消失，不必問。**這種題目留到下一輪**，不要在這一輪先用猜的問法
（「如果要同步，方向限制是什麼」）把它問掉，那樣使用者答完你還是不知道答案對不對。

一輪問完，等使用者全部回答，再判斷有沒有新解開的題目要問下一輪。沒有懸而未決的決策題了
（frontier 淨空），才算追問結束，把答案分別併入對應章節（見步驟 2、3、6），繼續往下寫。
不要邊寫 AGENTS.md 邊插著問——問完一輪、確認完，才進下一步驟。

## 這份技能常見的決策題範例

**步驟 1（解析估算表）**：`extra` 裡收到的內容判斷不出屬於備註還是驗收時：

```
❓ **Q1** - **K/L 欄內容歸屬**：第 7 列「K 欄」寫著「符合公司資安政策」，但欄名是空的，
內容看起來像驗收標準，不像備註。這條要算進 §4 的驗收標準，還是 §6 的備註說明？

➡️ 併入驗收標準——它是可驗收的陳述句（「符合...」），備註通常是操作說明或工具名稱。
```

**步驟 2（判斷作業性質）**：這一題**每個專案都要問**，不是只有動詞混合時才問——
即使估算表用詞看起來很像唯讀健檢，也要讓使用者拍板，因為「唯讀健檢」「日常維運」
「變更型導入」三種對 §10 的最小權限、能不能執行操作，寫法完全不同：

```
❓ **Q1** - **本專案的作業性質**：估算表動詞以「檢視、盤點」為主，看起來像唯讀健檢，
但也可能是要接手後續的日常維運，或是一次性的變更型導入專案。請確認屬於哪一種：
(a) 唯讀健檢／稽核　(b) 日常維運（需要執行既定維運操作的權限）
(c) 變更型導入／專案執行　(d) 混合（請指出哪些項次屬於哪一種）

➡️ 建議答案：(a) 唯讀健檢／稽核——估算表動詞以檢視盤點為主，備註欄也沒有提到
需要持續執行的維運項目或變更排程。
```

動詞混合、無法一眼判定唯讀或變更型的個別項次，另外追問：

```
❓ **Q2** - **項次 5「檢查並調整防火牆規則」的性質**：「檢查」是唯讀，「調整」是變更，
這條要算變更型（需要變更視窗與回復計畫），還是先唯讀盤點、調整另外報價？

➡️ 算變更型——估算表把兩個動詞寫在同一項次同一份工時裡，代表客戶已經為「調整」付費，
不能把它默默降級成唯讀後才發現漏做。
```

**步驟 3（補齊資訊）**：見 SKILL.md 步驟 3 列出的四類缺口，皆屬決策題，附建議答案後
一輪問完；「是否同步外部平台」與「同步方向限制」則分屬前後兩輪（見上）。

## 事實自己查，不要假借問句之名

反面示範：「你們有沒有安裝 vmware 相關技能？」——這是能用 `ls ~/.claude/skills/` 一秒查到
的事實，不該問。只有查完之後，發現本機沒裝、skills.sh 也搜不到合適的，才輪到問使用者
「這個缺口要留白誠實寫，還是有其他管道我不知道的技能可以裝？」——這才是真決策。
