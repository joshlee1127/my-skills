# 2. 工作流程

針對每一個{{實作／盤點}}需求：

1. 閱讀 `AGENTS.md`。
2. 閱讀使用者明確提到的技能（skills）。
3. 從核准的技能清單中，閱讀明顯需要的支援技能。
4. 檢視相關{{程式碼／既有資料}}。
5. 只有在任務有明顯歧義時，才提出一個聚焦的問題。
6. 在 `prompts/` 中建立一個詳細的提示檔案。
7. 詢問：「我已在 prompts/`<file-name>`.md 準備好提示。可以執行了嗎？」
8. 獲得核准後，重新閱讀該提示檔案，並嚴格依此執行。
9. 執行可用的檢查（見 §11）。
10. 分享測試或驗證已完成項目的確切步驟。

除非使用者明確表示要跳過提示建立步驟，否則不要在建立提示之前就開始動手。

# 12. 進度與紀錄

所有作業進度統一記錄在專案根目錄的 `progress.md`，不得散落在其他檔案或僅存在對話紀錄中。

## 動作前檢查

- 開始任何動作前，先讀取 `progress.md`，確認目前進度、已完成與未完成項目，避免重複或遺漏。
- 若 `progress.md` 尚不存在，先建立一份再繼續。

## 更新時機

- 每個動作開始前：新增一筆「進行中」紀錄。
- 每個動作完成後：更新為「已完成」並補上結果摘要（不得寫入機敏資料）。
- 動作中止或延後時：更新狀態並註明原因。

## 格式

以表格或條列記錄，每筆至少包含：日期、作業項目（對應 §1 分類）、狀態（進行中／已完成／延後）、備註。

## 分離原則

`progress.md` 只記錄進度與狀態，不得包含帳密、金鑰、Token；機敏資訊處理依 §9、§10。
