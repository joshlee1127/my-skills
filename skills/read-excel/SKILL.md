# 讀 Excel（.xlsx／.xlsm）

## 這個技能要解決的問題

直接把 .xlsx（其實是 zip + XML）當文字讀，拿不到人看得懂的內容；用完整的試算表編輯工具
處理「只是想看資料」的需求，又太重、太慢，尤其是活頁簿很大或工作表很多的時候。

`scripts/read_excel.py` 是一支唯讀、只管把格線資料忠實搬出來的小工具：不猜欄位語意、
不假設任何表格結構，也不修改檔案。

## 什麼時候不要用這個技能

- 需要**建立或修改** Excel 檔案 → 用 document-skills:xlsx。
- 檔案是**工時估算表**，需要依「項目分類／項次／作業項目／備註／驗收項目／工時」的
  欄位語意解析 → 用 create-agents 技能自帶的 `read_estimate.py`。那支腳本處理了
  估算表特有的標題列位移、分類合併儲存格、小計列等坑；這個技能只管把資料忠實倒出來，
  不做語意判斷，硬套上去只會把估算表解析錯。

## 流程

### 1. 先列出工作表，看清楚有幾個 sheet、各自多大

```bash
python <skill>/scripts/read_excel.py <path> --list-sheets
```

回傳每個工作表的名稱、列數、欄數、合併儲存格數量。活頁簿有多個工作表時，
先看這個再決定要 `--sheet` 哪一個，不要預設只有第一個工作表有資料。

### 2. 傾印指定工作表

```bash
python <skill>/scripts/read_excel.py <path> --sheet <name>
```

預設行為：第一列當標題、合併儲存格會展開填值（被合併蓋住的儲存格會拿到左上角的值，
不會顯示空白）、輸出 Markdown 表格、最多顯示 500 列。超過 500 列不會靜默截斷——
結果裡會註明還剩幾列，需要更多就調整 `--max-rows` 或用 `--range` 縮小範圍。

### 3. 依需要加參數

- `--range A1:D50`　只看特定範圍
- `--header-row 2`　標題不在第一列時指定（1-based）
- `--no-header`　不當表格看，直接看格線原始值
- `--format json`　輸出結構化資料（`header` / `rows`），供程式接續處理
- `--max-rows 0`　不限制列數（活頁簿真的不大時才用，避免不小心把巨大結果灌爆對話）
- `--fast`　檔案很大又不在意合併儲存格時，改用 openpyxl 的 read_only 模式讀取，
  明顯更快，但代價是合併儲存格不會展開（openpyxl 的限制，read_only 模式讀不到
  合併範圍資訊）
- `--out <path>`　寫檔而非印到終端——Windows 主控台預設 cp950，管線接給另一支程式
  容易把中文解碼成亂碼，需要接續處理就用這個

## 常見誤區

**合併儲存格看起來是空的，就以為那幾列沒資料。** 手工維護的 Excel 很常把分類名稱、
跨列的說明只打在合併範圍的左上角，其餘儲存格在檔案裡真的是空值。這支腳本預設會把
左上角的值展開填到被合併蓋住的儲存格；只有加了 `--fast` 才會停用這個行為。

**拿這個技能去解析工時估算表的欄位語意。** 這支腳本不知道哪一欄是「項次」、
哪一欄是「驗收項目」——那是 create-agents 技能 `read_estimate.py` 的工作。
這個技能只保證「格線裡有什麼就倒出什麼」，語意判讀留給呼叫它的人或其他技能做。

**為了省事一律加 `--fast`。** 大部分工時估算表、確認表這種手工維護的檔案都有合併儲存格，
關掉合併展開反而會讀出一堆看似缺漏的空格。只有確定檔案很大、且結構工整沒有合併儲存格時才加。
